## Spec change — film length, scene length, paywall (later same day)

After designing the player around the original ≤ 3 min film / 15 s scene
spec, we walked through the math on a few candidate film lengths and
free-content wedges. Settled on a single locked v1 spec:

- **Micro film:** ~15 minutes total runtime (was: ≤ 3 min).
- **Scene:** 45–90 seconds, default 90 s (was: locked at 15 s).
- **Free wedge:** first **3 scenes** free.
- **Pass:** $2.49 unlocks every scene of one micro film.
- **All-access:** $9.99/mo unlocks every scene of every film.

We also deleted "episode" and "series" from the product vocabulary. We
make films, not shows. The watch page used to be modeled as a series of
short micro film episodes (ReelShort-style); it is now modeled as a
single film whose scenes are progressively unlocked. Same UI affordance,
different framing — it is one film, not a show.

## Cap micro films at 10 minutes (later same day)

Films can run much shorter — a single 90-second beat, a tight three-
minute essay, a full-length nine-minute thriller all qualify — but
nothing exceeds the cap. This is the right cinema-of-the-phone
runtime: long enough to hold a real arc, short enough that a viewer
will actually finish.

- **The cap is 10 minutes, not 9, not 12.** Cleaner verbal handle

## Screenplay editor (later same day)

Every micro film starts with screen writing — a screenplay. Added a
dedicated workspace for it at `/studio/screenplay`.

### Two modes (both shipping in v0.1)

- **Generate from a guided prompt** — short structured form (logline,
  genre, tone, lead character, target runtime up to 10 min) → POST to
  `/api/screenplay` with `{ mode: "generate", prompt }` → returns a
  full Screenplay (title, logline, characters, eight scenes with
  scene heading, action, dialogue, duration). User lands in the
  editor with the draft loaded.
- **Co-write with assistance** — start blank with one empty scene.
  Each scene card carries inline actions: Rewrite, Tighten, Extend,
  Suggest a turn. Each routes through `/api/screenplay` with
  `{ mode: "rewrite" | "tighten" | "extend" | "suggest_turn", scene }`
  and the response replaces just that scene, with a per-scene busy
  state during the roundtrip.

### Files added

- `lib/screenplay.ts` — Screenplay / ScreenplayScene / ScreenplayCharacter
  / DialogueLine types; `emptyScreenplay`; `blankScene(n)`;
  `estimateRuntime(scenes)` (parses "1m 12s" / "60s" labels and emits
  a "9 min 40 sec" total); `mockGenerateScreenplay(prompt)` (an
  eight-scene deterministic draft sized to the requested target
  runtime); `mockRewriteScene(scene, instruction)`.
- `app/api/screenplay/route.ts` — POST handles all modes, returns
  v0.1 mock JSON with a 350 ms latency simulator so the UI loading
  states are visible. GET returns service metadata. Comment block at
  the top documents the ESY wiring target and the model-pinning rule
  (no `*-latest` aliases when wired).
- `app/studio/screenplay/page.tsx` — server shell with metadata,
  breadcrumb, page header, and a Talk-to-us escape hatch.
- `app/studio/screenplay/screenplay-editor.tsx` — client component.
  Three views: ModePicker (cards for each entry mode) → GuidedForm
  (the structured prompt) → Editor (scene cards). Editor lifts
  screenplay state, runtime estimate (with an over-cap warning when
  the sum of scene durations exceeds 10 min), per-scene assist
  loading state, add/remove scene, start over.

### Files updated

- `app/studio/page.tsx` — hero subtitle reframed to "Roll a film,
  end to end." A prominent "Open the screenplay editor →" CTA sits
  in the hero with a "Step 02 — Develop" tag so the workflow link
  is explicit.
- `lib/workflow.ts` — Develop step description now leads with the

  scenes — yourself with assistance or from a guided prompt. Cast a

- `docs/style-guide.md` — Screenplay added to the vocabulary table;
  new note: "The screenplay is the noun. We do not call it a script.
  Verbs are concrete craft actions — Write, Rewrite, Tighten, Extend,
  Suggest a turn — never generic AI verbs like magic or improve."
- `README.md`, `docs/README.md` — Screenplay added to vocab; routes

### Decisions

- **Screenplay, not script.** Cinematic noun. Already locked into the
  style guide.
- **Two modes, not one.** "Write with assistance" and "Generate from
  a guided prompt" are both first-class, picked from a single mode
  picker. The user explicitly named both as desired entry points.
- **Eight scenes by default in the mock.** Matches the showcase
  film's curated structure (~9m 55s under the 10 min cap). Real
  generator will scale scene count to the requested runtime.
- **Mock the AI roundtrip locally for v0.1.** Deterministic returns
  + 350 ms simulated latency. The UI is fully exercised today; the
  wire to ESY is a single function swap when the endpoint exists.
- **No `script` anywhere.** Avoid the word entirely in copy and code
  to keep the vocabulary consistent.
- **Per-scene assist actions are concrete craft verbs:** Rewrite,
  Tighten, Extend, Suggest a turn. No "Magic", no "AI", no
  "Improve."
- **Scene editor uses mono font for action + dialogue.** Visually
  it should read like a real screenwriting tool (Highland, Final
  Draft) rather than a generic AI chat surface.
- **Runtime estimator surfaces a cap warning.** If the sum of scene
  durations exceeds 10 min the runtime pill turns crimson. A soft
  signal, not a hard block — writers can deliberately exceed during
  drafting.

## Cover workspace (ChatGPT Images 2.0)

Added a cover art workspace at `/studio/cover` for generating and
editing the 9:16 vertical cover of a micro film. The cover is the
poster in the showcase grid, the OG image when shared, the first
visual a viewer ever sees of the film. Two product modes:

1. **Generate** — text prompt + optional style + optional palette →
   new 9:16 cover.
2. **Edit** — selected cover + plain-language instruction → new
   variant. The original is kept; edits chain via `sourceCoverId` so
   we can show "Original" vs "Edit" in the gallery.

v0.1 returns SVG data URIs composed locally from a curated palette
set (Amber noir, Neon rain, Moonlit blue, Rust & rose, Celluloid
warm, Graphite). Each mock cover renders a vertical gradient,
radial accent, vignette, fractal-noise grain, eyebrow text,
title placeholder lifted from the prompt, and a subtitle line.
Mock dimensions are 1024x1536 — the gpt-image-2 vertical size we'll
request in production.

  `CoverEditRequest`), palette table, `mockGenerateCover` and
  `mockEditCover`, SVG composition + URI encoder.
- `app/api/cover/route.ts` — POST endpoint with `generate` and
  `edit` modes. Header comment cites the ESY architecture and the

- `README.md`, `docs/README.md` — Cover added to vocab; routes

### Decisions

- **Cover, not poster / thumbnail / key art.** Cinematic noun
  matching the brand cadence (micro film, micro scene, screenplay,
  cover). Locked into the style guide.
- **9:16 vertical, 1024×1536, end of story.** Matches the film
  format and gpt-image-2's vertical output size. Don't introduce
  a horizontal cover — the cover lives where the film lives.
- **Edits produce new variants — never destructive.** Each edit
  is a child cover linked by `sourceCoverId`. The gallery shows
  every step of the chain so the writer can compare and revert.
- **Name the model in copy.** "Edited with ChatGPT Images 2.0"
  appears in product copy as a quality signal. Per the model-
  pinning rule, the wired implementation uses the dated snapshot
  `gpt-image-2-2026-04-21`; the marketing name stays the friendly
  one.
- **Mock generator produces real-looking SVG covers.** Cinematic
  gradients + grain + type, not placeholder boxes. The gallery
  must look credible from day one because the cover surface
  is what convinces a brand the platform is serious.
- **One curated palette set instead of unlimited freeform.**
  Amber noir, Neon rain, Moonlit blue, Rust & rose, Celluloid
  warm, Graphite. Picked for cinematic coverage; chosen
  deterministically from the prompt hash if not specified.
- **Edit suggestions are concrete cinematography, not generic
  AI verbs.** "Push the palette warmer", "Move the light source
  to the left", "Tighten the composition." Same rule that
  governs the screenplay's per-scene actions.

### Decisions

- **Cite a single canonical source.** Baidu Baike is the most
  comprehensive single reference for the form. We cite it, link
  to it, and stop. We do not paper over the fact that translations
  on the linked page are AI-assisted — we say so explicitly.
- **Standard says 8–15; we cap at 10. Both true.** The page leads
  with the encyclopedic standard, then notes that critics already
  call ten the practical ceiling, then states our cap with a
  one-paragraph rationale. We do not relitigate the cap, and we do
  not frame 12- or 15-minute films as "not micro films" — they are.
  Ten is our choice, not the form's outer edge.
- **Our place section, not a marketing section.** The About page
  ends with a single paragraph each on micro.film and Micro Film
  Studios. No use cases, no testimonials. Visitors who want the
  pitch can hit the landing.
- **Internal citations always go to `/about`.** External writers
  citing micro.film should land on our page, not on the wiki. The
  style guide enforces that.
